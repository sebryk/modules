# Backend

NestJS, Prisma и PostgreSQL. Требуется Bun 1.4.2 и настроенный `DATABASE_URL` в `.env`.

```bash
cd backend
bun install --frozen-lockfile
bun run prisma:generate
bun run start:dev
```

После установки запускайте `prisma:generate` явно: install-скрипты зависимостей отключены в `bunfig.toml`, чтобы чистая установка не падала на скрипте `argon2`.

Для сборки и запуска: `bun run build`, затем `bun run start`.

Проверки: `bun run lint` и `bun run test`. Миграции и заполнение базы: `bun run prisma:migrate:dev` и `bun run prisma:seed`.

## Пользователи

В ответах `/users`, `/users/:id` и `/auth/me` пользователь содержит `status`
(`active`, `invited`, `vacation`) и `avatarUrl` (HTTP(S)-ссылка или `null`).
Статусы описывают сотрудника и не меняют правила авторизации.

В `POST /users` и `PUT /users/:id` оба поля необязательны. При создании
по умолчанию используются `status: "active"` и `avatarUrl: null`. При обновлении
пропущенное поле сохраняет текущее значение; `avatarUrl: null` очищает ссылку.
Ссылка должна содержать протокол `http://` или `https://` и не превышать 2048 символов.
`status: null` недопустим. Остальные обязательные поля создания и обновления,
включая пароль и роли, сохраняют прежний контракт.

### GET /users

Требуется авторизация и разрешение `user:read`.

| Параметр    | Описание                                                             | По умолчанию         |
| ----------- | -------------------------------------------------------------------- | -------------------- |
| `search`    | Поиск по имени, фамилии, email и должности без учёта регистра        | Без поиска           |
| `position`  | Точное совпадение должности; должность остаётся произвольной строкой | Все должности        |
| `status`    | `active`, `invited`, `vacation`                                      | Все статусы          |
| `sortBy`    | `name`, `position`, `email`, `status`, `createdAt`                   | `createdAt`          |
| `sortOrder` | `asc`, `desc`                                                        | `desc`               |
| `page`      | Целое число от 1                                                     | `1`                  |
| `pageSize`  | Целое число от 1 до 100                                              | `10`                 |
| `include`   | `role-assignment` добавляет назначения ролей                         | Без назначений ролей |

Фильтры объединяются через AND. В `search` пробелы по краям игнорируются,
каждое слово должно встречаться хотя бы в одном из полей поиска. Например,
`Иван Петров` находит пользователя с именем `Иван` и фамилией `Петров`.
Пустой или состоящий из пробелов поиск не ограничивает выборку.
Символы `%`, `_` и `\` ищутся буквально, а не как SQL-шаблоны.

`name` сортирует по имени, затем фамилии; статусы в порядке возрастания идут как
`active → invited → vacation`. Последним критерием всегда служит `id asc`,
чтобы записи с одинаковыми значениями сохраняли стабильный порядок.

Примеры запросов (значения параметров должны быть URL-encoded):

```http
GET /users
GET /users?status=active&sortBy=email&sortOrder=asc&page=2&pageSize=5
GET /users?search=%D0%98%D0%B2%D0%B0%D0%BD%20%D0%9F%D0%B5%D1%82%D1%80%D0%BE%D0%B2&include=role-assignment
```

Ответ всегда содержит `data` и `meta`, в том числе при запросе без параметров:

```json
{
   "data": [],
   "meta": {
      "page": 1,
      "pageSize": 10,
      "total": 0,
      "totalPages": 0
   }
}
```

`total` — количество записей после фильтрации, до пагинации; `totalPages` —
округлённое вверх `total / pageSize`. Страница за пределами списка возвращает
пустой `data`, сохраняя запрошенный номер страницы и фактические итоги.
Некорректные значения параметров возвращают HTTP 400, отсутствие авторизации —
401, отсутствие разрешения — 403.

**Изменение совместимости:** запрос без параметров теперь возвращает только
первую страницу из 10 записей. Для получения всего списка нужно обходить страницы.

Перед запуском обновлённого бека примените миграции (`bunx prisma migrate deploy`)
и сгенерируйте Prisma Client (`bun run prisma:generate`). Миграция добавляет
существующим пользователям статус `active` и пустую ссылку на аватар.
